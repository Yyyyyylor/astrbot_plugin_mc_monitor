## AstrBot桌面端实际验证

通过桌面端原生“从文件安装”入口安装交付ZIP，使用独立的模拟日志文件、空接收者、关闭的LLM和网络探测。没有启动第二份AstrBot、重启桌面端或修改宿主源码。现有全局配置的未保存修改由用户自行处理后，才进入插件管理操作。

| 检查 | 实际结果 |
| --- | --- |
| 安装与依赖 | 插件1.0.0加载成功；桌面端已有依赖，无需另行安装；官方装饰器和五个命令注册成功 |
| 原生配置界面 | 检查了监控、日志、Docker、Java状态、RCON、QQ目标、重试、安静时段、绑定、Provider/人格选择入口、阈值及逐事件设置的实际渲染；保存路径、间隔和开关后，配置文件值正确，AstrBot自动重载该插件 |
| 日志识别 | 启动、进入、白名单拒绝、认证失败、踢出、封禁、退出的固定日志产生7个事件；真实UUID字段保持原值，重复进入行及聊天伪造文本被忽略；在线状态与测试日志一致 |
| 轮询去重 | 多次轮询保持7个事件，空接收者的待发记录始终为0 |
| 文件轮转 | 旧日志新增进入行后立即轮转，新日志写退出行；旧文件未读尾部及新文件均读到，总数7→9，没有日志缺口事件 |
| 插件重载续读 | 点击本插件重载；后台记录旧实例terminated、新实例initialized；不重播已有9个事件，追加进入行后只增至10个 |
| 来源中断恢复 | 暂时移走测试日志，连续失败达到阈值时只增加一次采集异常（10→11）；额外失败轮询不重复；恢复文件后增加一次恢复（11→12），在线完整性取消 |
| 配置热更新 | 直接修改本插件配置文件为无效轮询间隔0，日志报告config_invalid且上一份有效设置继续采样；写入有效关闭设置后采样时间停止变化，无需重载 |
| 不可用指标 | 未启用指标来源时TPS、CPU等保存为null，未生成模拟性能数值 |
| 停用 | 在插件管理停用本插件，AstrBot调用terminate并记录terminated；没有停止其他插件或宿主进程 |
| 连接释放修复 | 收尾发现SQLite事务上下文本身不关闭连接，已增加显式close；70项测试通过后，在桌面端重新加载修复版，原有12个事件不重放，追加退出只增加一次至13个，再次停用 |

模拟日志和读出的SQLite状态仅用于验证解析与恢复，不代表真实MC事件或消息送达。测试使用的事件数量不包括任何QQ/LLM联调。测试结束保留插件安装但停用，监控开关关闭，接收者为空、LLM关闭，日志路径恢复默认；模拟数据库与配置备份移入工作区`.pytest_cache/desktop-20261011/`，不进入安装包。

配置文件热更新针对插件运行设置；AstrBot的配置面板可能仍显示宿主内存中的旧值。手工改文件后需要插件重载再打开面板，避免将旧面板值保存回文件。正常通过面板保存会由宿主重载插件，已在本版本验证。
